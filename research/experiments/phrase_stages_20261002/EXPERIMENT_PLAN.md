# V4 extraction demonstrations: frozen development experiment

## Question and intervention
The completed v3 pipeline returned a validated empty extraction in 30/38 cases. Its only explicit JSON example had zero spans. Empty-example anchoring is one plausible explanation; model capacity, task ambiguity and other prompt effects remain alternatives. This experiment appends eight original contract demonstrations to the extraction system prompt: four stance-present and four stance-absent examples. It does not establish the causal mechanism of any change.

The extraction instructions preceding the examples remain byte-identical to v3. Direction and speaker prompts, schemas, exact alignment and unique occurrence anchors, candidate cap, no-normalization rule, stage processing, model, embedded chat template, seed, temperature, context and output reservations remain unchanged. No output repair, keyword extraction, label inheritance, filtering or retry is allowed. Any failure remains in the fixed denominator. The runner/provenance/test files differ only to isolate and bind this experiment and preserve its own records.

## Inputs and isolation
Use only the same 26 original and 12 former-transfer synthetic development cases from the frozen v3 record. Both suites have already been reused in development. No sealed89, 726, corpus validation or held-out data may be opened. Demonstrations are newly authored illustrative inputs, with different complete text and policy topics from the 38 cases; they are never added to evaluation. Existing v3 raw/public records remain intact. All writes stay in this isolated folder except the existing wrapper's distinct server log in runtime_cpu. No main checkout, GitHub, serving or deployment changes.

## Frozen execution
Use existing pinned CPU llama.cpp b11349 and Qwen3-4B-Instruct-2507 Q4_K_M bytes. Verify wrapper, binary, checkpoint, source, protocol and fixture hashes before inference. Run structural and provenance tests first and obtain independent AI design review. Check process state and coordinate one heavy runtime. Execute every fixed case once in its existing order. Preserve each raw model output, exact input tokens, stage status, timing and failure. No semantic run resumption or selective repeat. Recompute publication metrics from raw final predictions and preserve the raw record.

## Evaluation and claims
Primary: exact source start/end + direction + attribution recovery out of all 27 expected spans, plus exact author-only recovery out of all 21 expected author spans, each using the original evaluator and unchanged denominators. Also report all-case coverage, exact cases, candidate extraction boundaries, empty extractions and no-expected-span false highlights. Compare v3 and v4 on identical rows and evaluator functions. Report suites separately and together. Do not replace exact metrics with overlap scores or accepted-only accuracy.

Secondary: existing labeled-attributed IoU >= 0.5 and axis-specific exact diagnostics remain unchanged. An independent AI reviewer additionally assesses every final emitted span against the full source and synthetic expected clauses, and audits all candidate extractions for unsafe scope. Each emitted span receives one category: exact/minimal, broader semantically adequate, unsafe/incomplete, spurious, or uncertain. Broader adequacy requires the same political claim, direction and discourse voice, intact full negation/qualification, no unrelated additional claim, and exact source alignment. Punctuation-only widening can qualify. One-to-one expected/predicted matching is required; no double counting, normalization, repair or metric override. Where a shorter or alternative clause may be semantically adequate but fails this conservative rubric, mark uncertain and disclose it. Summarize this as qualitative AI diagnostic review, never human gold or independent accuracy.

## Decision and stopping rule
A completed run plus independent output review establishes this experiment's result. An improvement may justify further development; it cannot approve release. Lower recall, new polarity/voice errors, or more unsupported highlights are reported, not hidden. All serving/release gates remain false. Next experiments, if warranted, require a new frozen protocol and must not reopen this run. Deployment readiness still requires independently annotated contemporary data, rights review and operational validation.
